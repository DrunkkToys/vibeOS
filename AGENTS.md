## WORKFLOW — Stale Bootstrap Token Cleanup

### Root Cause
A stale `.env.alpha` file at `$VIBEOS_HOME/.env.alpha` containing
`VIBEOS_API_BOOTSTRAP_TOKEN=vos_...` (a literal placeholder with three dots)
takes priority over the valid `EMBEDDED_API_TOKEN` constant in
`api-client.ts:12` because `readBootstrapTokenFromDisk()` returns the disk
value first. The bootstrap exchange then fails with `INVALID_TOKEN_FORMAT`
(HTTP 400), which sets `_apiFallbackMode = true`, making `isApiConnected()`
return `false` and hiding the `⚡` flash icon.

### Fix (2 parts)
1. **Delete `$VIBEOS_HOME/.env.alpha`** — lets the code fall through to the
   valid `EMBEDDED_API_TOKEN` on the next bootstrap exchange.
2. **Add token validation in `readBootstrapTokenFromDisk()`** at
   `src/lib/api-client.ts:596` — reject tokens that don't match
   `/^vos_[0-9a-f]{64}$/` (i.e. `vos_` + exactly 64 hex chars), so a stale
   placeholder can never silently block the embedded fallback again.

### Verification
- `curl https://api.vibetheog.com/health` → HTTP 200
- Footer shows `| VibeUltraX ⚡` (flash icon after brand)
- `vibe status` shows no `⚠` warning
- Bootstrap exchange returns HTTP 200 with a valid `api_token`

### Runtime Fix — Sync stale bootstrap token
Even after fixing `readBootstrapTokenFromDisk()`, a running process that loaded
the stale value at module init retains `VIBEOS_API_BOOTSTRAP_TOKEN = "vos_..."`
indefinitely because `syncApiTokenFromDisk()` uses `||=` which never overwrites
a truthy value.

**Fix in `src/lib/api-client.ts:793-800`** — In the `else` branch of
`syncApiTokenFromDisk()`, force-overwrite `VIBEOS_API_BOOTSTRAP_TOKEN` with

## WORKFLOW — Source-to-dist build for dev testing

### Root Cause
`npm run typecheck` runs `tsc --noEmit` (typecheck only, no emit). The
`scripts/ts-src-loader.mjs` prefers `dist-ts/` compiled output over source
when it exists, but `dist-ts/` may be stale from a prior emit run. Running
`node --loader scripts/ts-src-loader.mjs --test` after editing `.ts` files
silently serves stale compiled code.

### Fix
After editing source `.ts` files, always run `npm run build:dist` (which runs
`tsc -p tsconfig.json && tsc -p tsconfig.tests.json` with emit) before running
loader-based tests (`node --loader ... --test`) or E2E (`npm run test:e2e`).

CI's `test:ci` script already includes the emit step, so this only matters
during local development.
